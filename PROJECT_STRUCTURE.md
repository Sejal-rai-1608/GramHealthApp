## 📱 1. Flutter Client Application (`/GramHealth`)

The Flutter application is engineered using an **Offline-First Architecture**, modular services, and role-based screen partitioning.

### 📁 Root Configuration Files
- **`GramHealth/pubspec.yaml`**: Flutter package manifest detailing app dependencies (`sqflite`, `go_router`, `shared_preferences`, `http`, `connectivity_plus`, `geolocator`, `image_picker`).
- **`GramHealth/analysis_options.yaml`**: Linter configuration enforcing clean Dart code practices.
- **`GramHealth/lib/main.dart`**: Application entry point. Initializes `AuthGuard`, `ConnectivityService`, `SyncService`, and configures `GoRouter` declarative routing with localization delegates.

---

### 🌐 Internationalization (`lib/l10n/`)
- **`app_language.dart`**: Manages global language state (English, Hindi, Marathi, Gujarati) using `ValueNotifier` for real-time UI locale swapping.
- **`translations.dart`**: Centralized dictionary containing key-value translation strings for all 4 supported languages.

---

### ⚙️ App Configuration (`lib/config/`)
- **`app_config.dart`**: Centralized configuration handling backend URL switching between Production (`https://gramhealthapp.onrender.com`), ADB Reverse (`http://127.0.0.1:3000`), or LAN. Holds API endpoint constants.
- **`offline_ai_config.dart`**: Holds HuggingFace GGUF model download URLs, parameter defaults, and local cache paths for offline LLM execution.

---

### 💾 Data & Persistence Layer (`lib/data/` & `lib/repositories/`)
- **`data/local_database.dart`**: Centralized SQLite offline caching engine (`sqflite`). Maintains cached tables (`cached_consultations`, `cached_records`, `cached_prescriptions`, `cached_users`, `cached_doctors`, `cached_pharmacies`) and the offline `sync_queue`. Includes `clearAllData()` for strict multi-user privacy on logout/login.
- **`data/doctors_data.dart`**: Local fallback directory of doctors used during initial setup or offline lookup.
- **`repositories/offline_medical_repository.dart`**: Executes local SQLite queries for offline symptom lookup, prescription history, and cached medical records.

---

### 📦 Data Models (`lib/models/`)
- **`ai_response.dart`**: Model encapsulating AI chatbot answers, medical disclaimers, and suggested follow-up questions.
- **`clinical_response.dart`**: Structured SOAP note model for symptom triage (Subjective, Objective, Assessment, Plan, Risk Severity).
- **`local_model_status.dart`**: Data model representing download state and disk usage of on-device LLM models.
- **`medical_lexicon_entry.dart`**: Model mapping medical keywords, symptoms, remedies, and red-flag emergency symptoms for offline search.
- **`offline_model_metadata.dart`**: Metadata schema for on-device GGUF/ONNX model files.
- **`offline_response.dart`**: Result payload generated by the local offline safety and medical rules router.

---

### ⚡ Core Services (`lib/services/`)
- **`api_client.dart`**: HTTP wrapper that automatically attaches JWT bearer tokens to headers, handles timeouts, and formats API exceptions.
- **`ai_service.dart`**: Gateway service that routes queries to `POST /api/ai/query` when online, or delegates to `OfflineAiRouter` when offline.
- **`auth_service.dart`**: Handles User Login (`POST /api/auth/login`), Registration, Token Persistence in `SharedPreferences`, and triggers full SQLite cache clearing on session changes.
- **`connectivity_service.dart`**: Monitors device network connectivity state (`online`, `offline`, `weak`) in real time using `connectivity_plus`.
- **`consultation_service.dart`**: Handles Teleconsultation CRUD operations (list, request, accept, complete, update status).
- **`local_llm_service.dart`**: Manages on-device inference for offline LLM GGUF models.
- **`local_model_download_service.dart`**: Background downloader for HuggingFace model weights with progress tracking.
- **`medical_record_service.dart`**: Fetches, uploads, and manages patient electronic health records.
- **`offline_ai_router.dart`**: Smart router that evaluates user queries offline against emergency safety rules, medical lexicons, or local GGUF models.
- **`offline_ai_service.dart`**: High-level manager providing emergency keyword detection and offline medical fallback answers.
- **`offline_medical_lookup_service.dart`**: Performs fuzzy text matching against localized medical dictionaries offline.
- **`offline_safety_service.dart`**: Evaluates symptoms for red-flag warning signs (e.g. chest pain, severe bleeding) and triggers emergency alerts.
- **`pharmacy_service.dart`**: Searches nearby pharmacies, checks medicine stock availability, and syncs pharmacy inventories.
- **`prescription_service.dart`**: Handles creation, viewing, and digital signing of prescriptions.
- **`sync_service.dart`**: Background sync manager that queues offline mutations into SQLite and automatically drains/pushes them to the backend upon network reconnection.

---

### 🎨 Theme & Utilities (`lib/theme/` & `lib/utils/`)
- **`theme/app_colors.dart`**: Custom HSL dark-mode and glassmorphic palette definitions.
- **`theme/app_theme.dart`**: Material 3 theme configuration including custom typography, card styling, and input decoration.
- **`utils/auth_guard.dart`**: Router guard enforcing role-based page navigation and protecting restricted routes.

## ⚙️ 2. Node.js Express REST API & Prisma Backend (`/backend`)

The backend is built with **Node.js, Express, and Prisma v7**, backed by a **Supabase PostgreSQL database**.

### 📁 Root Files & Database Configuration
- **`backend/server.js`**: Application entry point. Loads environment variables, connects Prisma, and starts HTTP server on port 3000.
- **`backend/src/app.js`**: Express server setup. Configures CORS, JSON body parsers, global error handling, and mounts API endpoints.
- **`backend/prisma/schema.prisma`**: Comprehensive database schema mapping Prisma models: `User`, `Patient`, `Doctor`, `AshaWorker`, `Consultation`, `MedicalRecord`, `Prescription`, `Pharmacy`.
- **`backend/prisma.config.ts`**: Prisma client options configuration.
- **`backend/src/config/prisma.js`**: Singleton instance of PrismaClient for database connection pooling.

---

### 🎮 Controllers (`backend/src/controllers/`)
- **`ai.controller.js`**: Handles `POST /api/ai/query`. Queries Google Gemini API (or internal rule engine fallback) and returns structured response.
- **`asha.controller.js`**: Manages ASHA worker assignments, community patient lists, and health surveys.
- **`auth.controller.js`**: Handles User Registration (`POST /api/auth/register`) and Login (`POST /api/auth/login`) with bcrypt password hashing and JWT token signing.
- **`connectivity.controller.js`**: Endpoint `GET /api/connectivity` returning 200 OK server heartbeat status.
- **`consultation.controller.js`**: Manages teleconsultation requests, acceptance by doctors, status transitions (`PENDING`, `ACTIVE`, `COMPLETED`, `CANCELLED`), and doctor assignment.
- **`doctor.controller.js`**: Handles doctor lookup, profile management, and doctor schedule queries.
- **`medicalRecord.controller.js`**: Handles patient medical record uploading, fetching strictly scoped user records, and ABDM ABHA integration.
- **`patient.controller.js`**: Handles patient demographics, medical background, and emergency contact updates.
- **`pharmacy.controller.js`**: Handles pharmacy listing, distance calculation, and inventory lookup.
- **`prescription.controller.js`**: Creation and fetching of digital prescriptions with dosage details.
- **`user.controller.js`**: Admin user profile management (CRUD operations on user accounts).

---

### 🛡️ Middleware (`backend/src/middleware/`)
- **`auth.middleware.js`**: Exports `authenticate` (validates JWT Bearer token in header and attaches `req.user`) and `authorize` (restricts routes to specific roles e.g. `ADMIN`, `DOCTOR`).
- **`errorHandler.js`**: Global Express error handler formatting `ApiError` instances into clean JSON responses.
- **`notFound.js`**: Catch-all middleware returning 404 for undefined API paths.

---

### 🛣️ API Routes (`backend/src/routes/`)
- **`ai.routes.js`**: Defines `/api/ai/query` endpoint protected by `authenticate`.
- **`asha.routes.js`**: Route definitions for `/api/asha-workers`.
- **`auth.routes.js`**: Route definitions for `/api/auth/login` and `/api/auth/register`.
- **`connectivity.routes.js`**: Defines `/api/connectivity/health` ping endpoint.
- **`consultation.routes.js`**: Defines `/api/consultations` endpoints (create, list, accept, complete, status).
- **`doctor.routes.js`**: Defines `/api/doctors` endpoints.
- **`medicalRecord.routes.js`**: Defines `/api/medical-records` endpoints.
- **`patient.routes.js`**: Defines `/api/patients` endpoints.
- **`pharmacy.routes.js`**: Defines `/api/pharmacy` endpoints (inventory, list).
- **`prescription.routes.js`**: Defines `/api/prescriptions` endpoints.
- **`user.routes.js`**: Defines `/api/users` administrative endpoints.

---

### 💼 Business Services (`backend/src/services/`)
- **`auth.service.js`**: Handles password comparison via bcrypt, profile creation for patients/doctors/ASHA workers upon registration, and JWT signing.
- **`consultation.service.js`**: Implements consultation state transitions, doctor assignment logic, and role-based query filtering.
- **`doctor.service.js`**: Queries database for verified doctors matching specialty or location parameters.
- **`medicalRecord.service.js`**: Performs user-scoped database fetches for medical records with strict `patientId` authorization.
- **`patient.service.js`**: Database CRUD logic for patient profiles.
- **`pharmacy.service.js`**: Computes geographical proximity for pharmacies and manages inventory stock logic.
- **`prescription.service.js`**: Creates and formats digital prescriptions with medicine instructions.
- **`user.service.js`**: Administrative user account database operations.

---

### 🛠️ Backend Utilities (`backend/src/utils/` & `backend/src/constants/`)
- **`ApiError.js`**: Custom error class extending `Error` with HTTP status code and error type code.
- **`asyncHandler.js`**: Wrapper function catching rejected promises in async Express route handlers.
- **`consultationStatus.js`**: Finite State Machine enforcing valid consultation transitions (`PENDING -> ACTIVE -> COMPLETED`).
- **`pagination.js`**: Helper function constructing page offset, limit, and pagination metadata.
- **`consultation.js`**: Constants defining valid consultation risk levels (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`).
